本文记录：怎么核对的、证实了什么、修正了什么、还有哪些没验证。

> **核对日期**：2026-09-20
> **官方版本**：Lumina Studio `2.0.0-beta.20260911065539`（启动器 0.1.3 分发的本体）
> **核对方式**：**只读**读取本机已安装程序里的资源文件 —— 不运行本体、不反编译 exe、不联网抓取。

## 三、修正：三处调色板错误

参考图实测出的官方真值，修正了原来的估计值：

| 位置 | 修正前（估计） | 官方实测 |
|---|---|---|
| BW 黑 | `(0,0,0)` | `(20,20,20)` |
| CMYW 青 / 品红 / 黄 | `(0,255,255)` / `(255,0,255)` / `(255,255,0)` | `(0,134,214)` / `(236,0,140)` / `(244,238,42)` |
| C6(CMYWGK) 青/品红/黄/黑 | 同上近似 | 同上真值 |
| C8 槽 1/2/3/4 | 同上近似 | 同上真值 |

RYBW 与 C5EXT 的调色板**原本就与官方逐位一致**，无需修改。

### 修正的真 bug：6 色 RYBWGK 复用了 CMYW 的调色板

`C6R`（6 色 RYBWGK 配方）之前 `slots:"C6"` —— 与 CMYWGK 共用调色板。
按官方命名规范的槽位映射 `1→Red(5) 2→DeepBlue(6) 3→Green(7) 4→Yellow(3) 5→Black(4)`，
它应该是**白 / 红 / 深蓝 / 绿 / 黄 / 黑**。现已拆出独立的 `C6R` 调色板。

### 一条容易踩的官方差异（已在测试里记录）

**官方 8 色槽位值 ≠ 4 色 RYBW 的标准值**：

| 颜色 | 8 色槽位 | 4 色 RYBW 标准 |
|---|---|---|
| Red | `(193,46,31)` | `(220,20,60)` |
| DeepBlue | `(10,41,137)` | `(0,100,240)` |

命名规范给的是**槽位序号**，不是 RGB 值；每种模式有自己的显示调色板。
所以**不能用「8 色槽位的子集」去推 4 色 RYBW 的调色板**。

## 四、证实：正向模型与耗材档案结构

### 正向模型

官方 `bambulab_pla_stage_B.json` 里每个通道的参数是：

```json
{ "channel_index": 0, "color_name": "bambu green",
  "E": [0.019524, 0.448282, 0.040844],
  "k": [10.673121, 1.264406, 16.680016],
  "k_height_scale_gamma": 0.248934 }
```

**逐 RGB 通道一组 `E` / `k`** —— 这正是本项目 `tools/lumina_profile_writer.py` 的模型
`C(t) = E + (C0 − E)·exp(−k·t)`（每通道独立拟合 E、k）。✅

官方比我们多两项，**尚未实现**（属已知差异，不是 bug）：

- `k_height_scale_gamma`：层高对 `k` 的缩放。我们只在 0.08 mm 层高下验证过一致
- `neighbor_delta`：相邻通道对 `k` 的耦合修正（2.0 新增）
- 官方拟合是 `stage_A` → `stage_B` 两阶段 + Adam 优化器，我们是简化的一维 `k` 扫描
  （在 0.08 mm、单通道情形下与官方 1.x 结果逐位吻合，见 `--selftest`）

官方的验证字段也印证了我们修复 ΔE 的方向：`mean_delta_e` / `median_delta_e` /
`p90_delta_e` / `max_delta_e` —— 都要求 Lab 计算正确。

### 耗材档案结构

官方 `lumina-materials-seed.zip` 里的 `lumina_material_bundle.json`：

```json
{ "kind": "lumina_material_bundle", "schema_version": "2.0",
  "packages": [{
    "material_id": "mat_...", "revision_id": "rev_...",
    "content_hash": "sha256:...", "channel": "official", "visibility": "official",
    "local_directory": "拓竹/Bambu PLA Basic 黑色",
    "files": [ {"path": "...material.json", "role": "material_archive", "sha256": "...", "bytes": 36872, "required": true},
               {"path": "...stage_A_parameters.json", "role": "stage_a_parameters", ...} ] }] }
```

与本项目 `lumina_profile_writer.py` 写出/读取的字段（`kind`、`schema_version`、
`packages[].material_id/revision_id/content_hash/files[].role`）**结构一致** ✅
每个耗材包含 `material.json`（约 36 KB）与 `stage_A_parameters.json`（约 4 KB）。

## 五、尚未验证的部分（诚实说明）

- **梯度卡（单阶板）规格**：官方后端资源里**没有**任何梯度卡相关文件
  （关键字 `single_stage`/`gradient`/`stage_a.json` 在 assets 里 0 命中）。
  它属于**网页端功能**，不在本机磁盘上 —— 因此本项目梯度卡那一半的规格
  （3×6 / 10 mm 色块 / `step_layers` / 1340×680 图像）**仍未经官方数据核对**，
  只与官方导出的成品图逐字节对照过。
- **官方算法实现**：`lumina-backend.exe` 是编译后的，我们没有反编译它。
