# 自己测 RGB 手写 Lumina 耗材档案 · 完整指南

> 目标：**不依赖网站的图像识别**，你自己测量色块 RGB，离线生成能被
> Lumina Studio「导入耗材 ZIP」接受的耗材档案。
>
> 本指南里的数学不是猜的——正向模型是用**你自己导出的档案包**逐位反推并验证过的。

---

## 一、结论先说：可行，路线是这样

```
打印单阶板（白底 + 黑底各一块）
   ↓
自己测每个色块中心 RGB（36 个数）
   ↓
填进 CSV，用 lumina_profile_writer.py 离线拟合 E / k / C0
   ↓
生成 lumina_materials_1_<时间>.zip
   ↓
Lumina Studio → 耗材管理 → 耗材库 → 「导入耗材 ZIP」
```

**注意区分两件事**：「识别/提取」（网站看照片算色块）你不想要；
「导入耗材 ZIP」（把档案装进软件）这一步仍然需要，否则软件用不上这份档案。
导入是纯文件校验，不涉及图像识别。

## 二、正向模型（已逐位验证）

Lumina 的 Stage A 模型是每个基底、每个 RGB 通道各一条指数衰减曲线：

```
C(t) = E + (C0 − E) · exp(−k · t)          t 单位 mm
```

| 符号 | 含义 | 怎么来 |
|---|---|---|
| **C** | 该基底在厚度 t 处的线性 RGB | 你测的 |
| **C0** | 该基底**零厚度**处的线性 RGB | 由 t=0 实测值换算 |
| **E** | 渐近/饱和色，约束 **E ≥ 0** | 拟合 |
| **k** | 衰减系数，单位 **1/mm** | 拟合 |

三条关键规则（都经过验证）：

1. **C0 不是自由参数，它就是你 t=0 的实测值**，按下式换算：
   ```
   c = 实测8bit / 255
   线性 = c ≤ 0.04045 ? c/12.92 : ((c + 0.055)/1.055)^2.4
   ```
   实测验证：白底 t=0 测得 RGB = (212, 184, 115) → 线性 (0.658375, 0.47932, 0.171441)
   = 官方文件里的 `white_C0`，**逐位相同**。

2. **E 被约束在 ≥ 0。** 官方那份档案的蓝通道 `E = 0.0`，正是被这个约束钳住的。

3. **E、k 由白底和黑底两块板联合拟合**（两个基底共用同一组 E、k）；
   只有 C0 是每个基底各自一套。

### 验证证据（用官方导出包里的 samples 复算）

| 通道 | 拟合 E | 官方 E | 拟合 k | 官方 k | 拟合 RMSE | 官方 RMSE |
|---|---|---|---|---|---|---|
| R | 0.390213 | 0.390215 | 0.606452 | 0.606487 | 0.097488 | 0.097489 |
| G | 0.283142 | 0.283147 | 1.508721 | 1.508833 | 0.088381 | 0.088381 |
| B | 0.000000 | 0.000000 | 0.311096 | 0.311095 | 0.093348 | 0.093349 |

整体 `rmse_linear`：拟合 **0.093146995** vs 官方 **0.093147470**（差 7×10⁻⁷）。
`estimated_rgb` 也复现为 **[168, 145, 0]**，与官方完全一致。

> 附带发现：官方的 `rmse` 是**把 t=0 那两个零残差点也算进分母**的（共 36 个样本）。
> 只按 34 个非零点算会得到 0.100315 这类偏大的值。

## 三、你要测什么

### 板子规格（来自你的 SingleStage Kit `manifest.json`）

| 项目 | 值 |
|---|---|
| 网格 | **3 行 × 6 列 = 18 格** |
| 色块尺寸 | 10 mm |
| 间距 / 边距 | 1 mm / 1 mm |
| 层高 | **0.08 mm** |
| 底板 | 1.0 mm |
| 步进层数 | **0, 1, 2, …, 16, 25** |

### 18 个厚度（固定，不能改）

```
0.00, 0.08, 0.16, 0.24, 0.32, 0.40, 0.48, 0.56, 0.64,
0.72, 0.80, 0.88, 0.96, 1.04, 1.12, 1.20, 1.28, 2.00   （单位 mm）
```

**你要交的是 36 个 RGB**：白底板 18 格 + 黑底板 18 格。

### ⚠️ 顺序是这次最关键的坑

官方板上的排列是**行优先**：第 1 行 6 格是厚度 0…5 层，第 2 行 6 格是 6…11 层，
第 3 行是 12…16 层 + 25 层。

**我检查了你现有那份「金 petg hf」档案，它的样本序列物理上不成立**：

- R 通道白底有 5/17 次「越厚越亮」
- G 通道 8/17 次，B 通道 10/17 次
- G 通道有 10 处、B 通道有 11 处出现「白底比黑底还暗」
- 零厚度白底亮度均值只有 0.436（应接近纯白）

这不是耗材特性，这是**色块顺序/厚度对应错位**（或拍摄问题）。它直接导致
官方自己的警告：`Stage A 拟合误差较高`、平均 ΔE **8.72**、最大 ΔE **57.47**。
所以你想自己测，方向是对的。

**我的工具会强制按厚度对齐**：CSV 里用 `thickness_mm` 标定，厚度集合必须正好是上面那 18 个值，
对不上就直接报错退出——从根上避免位置错位。

## 四、怎么测

1. **打印两块板**：同一块单阶板，一块白底、一块黑底，**同一卷待测耗材、同层高、同配置、同方向**。
2. **测每个色块的中心**：避开边缘、缝隙、反光和高光。每个色块取一小块区域的平均值（不是单点）。
3. **固定条件**：同一设备、同一光源、同一曝光、同一白平衡；不要开滤镜/美颜/AI 增强。
4. **优先用色度计/分光光度计**直接读 sRGB；没有的话，用照片读数也可以，但要保证不过曝、不欠曝。
5. 用 **8bit sRGB（0–255）** 记数就行，工具内部会转线性。若你手上是 0–1 的线性值，加 `--linear-input`。

> 你可以直接从自己拍的照片里逐格读像素——这依然属于「自己测量」，
> 只是省掉了网站的自动识别。光照与曝光仍然决定成败。

## 五、用工具（3 条命令）

需要 Python 3（本机已有 3.12 + numpy）。

### 1) 先自检，确认模型实现没问题

```powershell
python lumina_profile_writer.py --selftest
```
应输出三通道 `OK` 且末行提示「模型实现与官方一致」。**每次升级脚本后都建议跑一次。**

### 2) 生成空白测量模板

```powershell
python lumina_profile_writer.py --make-template "测量模板.csv"
```
会得到 36 行（2 基底 × 18 厚度）的 CSV，把每格实测 RGB 填进 `r,g,b`：

```csv
substrate,thickness_mm,r,g,b
white,0.0,212,184,115
white,0.08,,,
...
black,2.0,,,
```

### 3) 生成档案包

```powershell
python lumina_profile_writer.py `
  --brand 大简 --name "金 petg hf" `
  --measurements "测量模板.csv" `
  --template "lumina_materials_1_20260917_153526.zip" `
  --out "lumina_materials_1_我的档案.zip"
```

- `--brand` 会成为耗材库里的**分组名**（建议填你自己的标识，方便以后一眼认出）
- `--template` 是**强烈建议**的：复用你导出包里的 `material_id` / `revision_id` /
  `content_hash`。原因是后端的 `content_hash` **不是**任何文件的哈希（我验证过：
  它不是 material.json 的、不是 stage_A 的、也不是两者拼接的），无法自行推算，
  所以复用你已验证过的标识最稳。
- 不加 `--template` 也能生成，脚本会自行派生这些标识；若导入被拒，就改用 `--template`。

## 六、导入

**Lumina Studio → 耗材管理 → 耗材库 → 「导入耗材 ZIP」**

后端会校验（Wiki 明确列的几项）：

1. ZIP 路径安全
2. 清单与材料目录完整
3. `material.json` 与拟合参数是有效 UTF-8 JSON
4. Stage A 参数满足求解器要求
5. **带版本清单的材料包，其文件尺寸和内容摘要是否匹配**

第 5 项是硬校验：清单里每个文件的 `sha256` 与 `bytes` 必须与实际文件一致。
**本工具已经正确处理**（生成后自测：`sha256=OK  bytes=OK`）。

导入成功后档案出现在**耗材库**；同名目录名已存在时不会覆盖，而是追加时间后缀另存一份。

> 如果导入仍然被拒：最稳的回退办法是把你生成的两个 JSON
> （`material.json`、`stage_A_parameters.json`）**塞回你原来那个导出 ZIP 里替换同名文件**，
> 再改 `lumina_material_bundle.json` 里对应的 `sha256` 与 `bytes` 两个字段。
> 这样其余字段与官方导出完全一致，只剩参数是你自己的。

## 七、生成的包里有什么

```
lumina_material_export.json                          导出清单
lumina_material_bundle.json                          材料包清单（含 sha256/bytes）
materials/<品牌>/<名称>/material.json                 档案主体
materials/<品牌>/<名称>/stage_A_parameters.json       E / k / C0 与验证信息
```

关键字段对应关系：

| 文件字段 | 含义 |
|---|---|
| `parameters.channels[0].E` / `.k` | 你拟合出的饱和色 / 衰减系数 |
| `parameters.substrates[*].C0` | 白底、黑底的零厚度线性 RGB |
| `material_summary.white_zero_rgb` / `black_zero_rgb` | 上面 C0 反算回 8bit |
| `material_summary.estimated_rgb` | 由 E 反算的 8bit 估算色（耗材库里显示的色块） |
| `validation.overall.*` | RMSE、ΔE 等诊断值 |
| `source.spec` | 板子规格（网格、层高、步进层数），**必须与实际打印一致** |

## 八、局限与注意事项

- **`material_summary.mean_delta_e` 我用的是 ΔE76**，官方可能是 ΔE00，所以这个诊断数字
  不会与网站完全同尺度。它只用于自检，不参与求解。
- **`content_hash` 无法自行推算**，只能复用模板值或接受派生值（见第五节）。
- **层高必须与打印一致**：这套流程固定 `0.08 mm`。若你用别的层高打印，`source.spec.layer_height_mm`
  和厚度列表都要跟着改，否则模型与实物不符。
- **E、k 是物理拟合量，不是实测 RGB**。你无法「直接填」E 和 k；必须通过 18 个厚度的
  序列拟合得到——这正是本工具做的事。
- **必须两块板都给全**。只有白底或只有黑底，无法分离「耗材自身衰减」与「基底反射」。
- **体检警告不要忽略**。它抓的正是你现有档案踩的那个坑。
- 文件是可读明文 JSON，方便你逐字段核对与版本管理。
