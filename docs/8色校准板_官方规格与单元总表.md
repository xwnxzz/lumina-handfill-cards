## 三、层序约定（最容易出错的地方）

来源：`core/calibration.py` 第 456–458、492–494 行。**官方注释原文**：

```python
# 约定转换：smart_8color_stacks.npy 存储底到顶约定 (stack[0]=背面，stack[4]=观赏面)
# 转换为顶到底约定 (stack[0]=观赏面，stack[4]=背面)，与 4 色模式统一
all_stacks = np.array([s[::-1] for s in all_stacks])
```

```python
# stack[0] = 观赏面 -> Z=0 (物理第 1 层，观赏面)
# stack[4] = 背面   -> Z=4 (物理第 5 层)
```

**结论**：

| 数据来源 | 层序 |
|---|---|
| `smart_8color_stacks.npy`（磁盘上的原始文件） | **底 → 顶**（[0]=背面，[4]=观赏面） |
| 校准板 / LUT / 2.0 的 `recipe` 数组 | **顶 → 底**（[0]=观赏面，[4]=背面） |

**我的实测验证**：把你打印的 2.0 Kit（`1号.json` + `2号.json`）拼成 2738×5 与官方 npy 比对：

- 正向逐行相同：**51 / 2738**
- **反序后逐行相同：2738 / 2738** ✅

即 **2.0 板顺序 = 官方 npy 的反序**，与官方代码的转换完全吻合。

> 这也解释了为什么前 8 行看不出差异——全白/全青/…/全绿这 8 行正反序是自己。
>
> ⚠️ **这是最危险的坑**：如果你拿 1.x 时代的资料（直接读 npy）去对 2.0 的板子，
> 5 层会整体颠倒，打印出来是**镜像反的**。用本目录的总表就按总表，别按 npy 原始行。

## 四、索引 ↔ 位置 ↔ 毫米坐标

来源：`calibration.py` 第 484–486 行 + `extractor.py` 第 251–265 行。

页码              page = i // 1369 + 1

## 五、提取时的几何（1.x，供理解软件怎么取样）

来源：`core/extractor.py` 第 218–276 行 `run_extraction()`。

- 目标画布 `DST_SIZE = 1000`（**1000×1000 正方形**）
- 四角点映射到**物理网格四角格的中心**，不是板子外缘：
  ```python
  half = DST_SIZE / physical_grid / 2.0
  dst = [[half, half], [DST_SIZE-half, half], [DST_SIZE-half, DST_SIZE-half], [half, DST_SIZE-half]]
  ```
- 每个数据格取样：归一化坐标 → 桶形畸变 `k = 1 + barrel·rad²` → `zoom` → `offset_x/offset_y`，
  然后取 **8×8 像素区域均值**（`cx-4 .. cx+4`）
- 可选 `auto_wb`（四角 50×50 白平衡）与 `bright`（Lab 亮度渐变补偿）
- 结果 `np.save(LUT_FILE_PATH, extracted)`，即 **`output/lumina_lut.npy`**

> **实用提示**：点四角时要落在**角格的中心**，而不是板子最外缘——这与人的直觉相反。

## 六、LUT 文件格式（1.x vs 2.0）

| | 1.x（仓库内） | 2.0（你的实例） |
|---|---|---|
| 格式 | `.npy` = `(N,N,3)` uint8 RGB 数组<br>`.npz` = `rgb` + `stacks` 两个键 | `.json`，含 `palette` / `entries` / `max_color_layers` / `base_channel_idx` / `layer_order` 等 |
| 8 色规模 | 每页 `(37,37,3)` | `entries` 2738 条 |
| 模式识别 | 按**数组尺寸**推断（`_detect_mode_by_size`） | 由 `color_mode` 字段声明 |

> 库内检索：`entries` / `max_color_layers` / `base_channel_idx` / `layer_order` **命中 0 处**
> → 你那份 `lumina_lut.json` 的 JSON 结构是 **2.0 独有**，1.x 没有对应物。

### 手动输入颜色是**官方支持**的做法

`core/extractor.py` 第 327–413 行 `manual_fix_cell(coord, color_input, lut_path)`：
读取 LUT → `lut[r, c] = new_color` → `np.save` 写回。
支持 `#RRGGBB`、`rgb(...)`、以及纯 16 进制三种输入。

> **意义**：官方 1.x 本来就允许你把**肉眼/仪器测到的颜色直接写进 LUT**，绕过拍照识别。
> 所以「自己测 RGB、离线构造数据」这条路是官方认可的用法，不是旁门左道。

## 八、单元配方总表的格式

> 这张表**不随仓库提供**（来源于官方套件文件，版权归原作者）。
> 保留下面的列说明，方便你自己从官方文件导出后对照。

表格共 2738 行，每行一个色块：

| 列 | 含义 |
|---|---|
| 全局索引 | 0–2737 |
| 页码 / 页内索引 | 1 或 2 / 0–1368 |
| 数据行 / 数据列 | 0–36（37×37 数据网格） |
| 物理行 / 物理列 | 1–37（39×39 物理网格，0 与 38 是边框） |
| 色块中心X_mm / Y_mm | 板面毫米坐标，便于定位量测 |
| 层1_观赏面 … 层5_背面 | 5 层耗材名称（**顶→底**，即实际叠放顺序） |
| 层1_ID … 层5_ID | 对应材料 ID 0–7 |

**自检**：与你实际打印的 2.0 Kit 逐行比对 **2738/2738 一致**。

### 用途

1. **核对板子**：拿到任一色块，查表即知它由哪 5 卷料、什么顺序叠成
2. **避免层序颠倒**：表里已是「顶→底」的最终约定，不用自己再翻转
3. **定位量测**：用毫米坐标找色块中心，减少对位误差
4. **判断页码**：结合右上角青/品红标记，确认照片属于第几页

### 现实提醒

2738 个色块逐个手工测量**不现实**。校准板/LUT 路线的实际意义是：
理解官方格式、核对已有数据、以及在少量失败色块上做定点修正（对应官方的 `manual_fix_cell`）。
**要真正做到「自己测量并建档」，实用路线仍是 36 个测点的梯度卡/单阶板**，
即 `lumina_profile_writer.py` 与 `lumina_singlestage_gui.html` 所服务的那条。
